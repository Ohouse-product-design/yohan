# 인테리어/생활 탭 개편 프로토타입

오늘의집 앱 `인테리어/생활` 탭을 **"시공 리드 퍼널"에서 "이사·집 준비 홈"으로** 재정의한 개편안.
`index.html`을 브라우저로 열면 됩니다. (React + Babel standalone, 빌드 불필요 — `apartment-ex`와 동일한 방식)

## 풀려는 문제

1. 계약 의사가 없는 이사 계획 유저가 이 탭을 **자주 방문**하게 만들 것
2. 원하는 메뉴를 **빠르게 찾게** 만들 것

## 현재안 진단

스크린샷 기준 모듈 12개 중 11개가 시공 리드. `생활`은 칩 3개가 전부다.

- **중복 진입점** — 견적계산기 4곳, 업체찾기 3곳, 직영시공 3곳. 모듈은 12개지만 실제 목적지는 6~7개.
- **탭 전체 지도(`전체서비스`)가 4번째 스크롤**에 아이콘 하나로 묻혀 있음.
- **유저 상태와 무관하게 항상 같은 순서**.
- **재방문 자산인 견적 순위 데이터가 최하단**.

## 재방문 엔진은 체크리스트가 아니라 견적이다

이 프로토타입의 첫 버전은 D-day 체크리스트와 진행률을 재방문 엔진으로 놓았다.
사내 기록을 확인한 결과 **그건 이미 두 번 시도해서 접힌 접근**이었다.

| 시점 | 무엇 | 결과 |
|---|---|---|
| ~2024 | **이사플래너** — 이사 일정에 맞춘 Action Item | 70%+ 액션 없이 이탈 → 2025-08 sunset (UP-109) |
| 2025-05 | 이사플래너 **온보딩 테스트** | 온보딩 CTR 11~20%, 알림 activate 8~9% → 롤백 |
| 2025-06 | 이사플래너 탭 **가치 테스트** (알림/검증/자가점검/혜택) | 최고가 알림형 19% → control 롤백 |
| 2024-09 | **이사클럽** — 이사 인증 쿠폰팩 멤버십 | 체리피커 문제로 운영 중단 |

두 번의 회고가 같은 곳을 가리켰다.

> 일정 알림보다 **업체 추천/견적 비교**가 핵심이었다 — 이사플래너 회고

> UXR: 유저들은 **체크리스트 기능을 다소 혼란스럽게 느끼며** (…) 알림 기능은 'must-have'보다 **'nice-to-have'에 가까울 가능성**. (…) '이사'는 현재 이사플래너처럼 **정량화된 one-size-fits-all 솔루션으로는 해결되기 어려운 문제일 가능성이 높음** — 2025-05 실험 종료 공유

> 지금 다시 만든다면 일정 관리나 노티를 강화하기보다는, 이사 일정을 입력하면 주요 업체의 **견적을 한 번에 받아보고, 업체들과 채팅으로 비교·조율**할 수 있는 경험에 더 집중했을 것 — 2026-06 #le-forum

그래서 L1을 **견적 트래커**로 교체했다. 재방문 이유가 억지 훅이 아니라 실제 대기 상태에서 나온다 —
업체 답이 오는 데 걸리는 시간은 실재하고, 유저가 실제로 요청한 항목만 트래킹하므로 one-size-fits-all도 아니다.

## 개편안 구조

| 층 | 내용 | 푸는 문제 |
|---|---|---|
| **L1** 견적 트래커 + 서비스 그리드 8칸 | 요청/응답 상태, 한 번에 견적 요청 | 재방문 + 빠른 탐색 (스크롤 0에 전체 지도) |
| **L2** 우리 단지 시세 | 평균가 + 6개월 추이 + 알림 | 내 견적을 판단할 기준 |
| **L3** 우리 동네 소식 | 반경 4km 새 리뷰·사례 + NEW 배지 | 신선도 (보조 훅) |

부수적으로 커머스 검색어(`집요한세일 ~91%`)를 탭 맥락 검색으로 교체.

## 프로토타입 조작

- **현재안 / 개편안 / 나란히** — 상단 세그먼트
- **견적 상태 `견적 0` `응답 대기` `비교` `계약 후`** — 견적 트래커의 4단계. 대기가 곧 돌아올 이유이고, 비교가 되면 시세와 대조되며, 계약 후엔 남은 항목으로 확장된다
- **주석 보기** — 현재안의 문제 지점(빨강)과 개편안의 대응(초록)을 화면 위에 표시
- `견적 0` 상태에서 항목 칩을 누르면 CTA가 실제로 바뀜
- 시세 그래프는 각 점에 hover하면 해당 월 값 표시

## 파일

```
index.html          진입점
app.jsx             루트 + 상단 컨트롤 바 + 디바이스 스케일링
data.js             더미 데이터 (현재안 재현 + 견적 트래커 4상태)
icons.jsx           아웃라인 아이콘 세트
ios-frame.jsx       iOS 디바이스 프레임 (apartment-ex 공용)
screens/shell.jsx   앱바 / 바텀네비 / 타일 / 주석 래퍼
screens/current.jsx 현재안 재현 (모듈 12개)
screens/redesign.jsx 개편안 (견적 트래커 + 시세 스파크라인 + 동네 소식)
```

데이터는 전부 더미입니다. 견적가·리뷰 수·시세 추이는 구조를 보여주기 위한 예시 값이지 실제 수치가 아닙니다.

## 아직 안 푼 것

- **이사 예정일 입력 흐름** — L1이 여기 걸려 있는데 이미 입력된 상태로만 그렸다.
- **무빙플래너와의 관계** — 현재 사람이 붙는 컨시어지 파일럿이 돌고 있고 초기 콜 전환 50%(N=14, 표본이 작아 아직 신호로 보긴 이름). 자동화된 일정표는 두 번 실패했고 사람이 조율하는 버전에 신호가 있다면, 이 트래커가 그 조율을 어디까지 대신할지는 별도 논의가 필요하다.
- **시세 카드의 표본 조건** — 표본이 얇은 단지에서는 오히려 신뢰를 깎을 수 있어 "N건 이상일 때만 노출" 같은 조건이 필요하다.
